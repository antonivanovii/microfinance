# Фронтенд

Два приложения в одном репозитории: `apps/client` — личный кабинет
(mobile-first), `apps/backoffice` — бэк-офис (desktop). Общие зависимости,
один lock-файл, один линтер, монорепозиторных раннеров нет.

Бэкенда пока нет — вся сеть перехватывается MSW.

## Команды

```bash
pnpm install

pnpm dev:client        # localhost:5173
pnpm dev:backoffice    # localhost:5174

pnpm typecheck
pnpm lint
pnpm test
pnpm e2e

pnpm check             # всё сразу, как в CI
```

## Стек

|                           |                                                                    |
| ------------------------- | ------------------------------------------------------------------ |
| React 19 + React Compiler | компилятор через Babel, не через экспериментальный Rust-порт       |
| TypeScript 6              | `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes` |
| Vite 8                    | конфиг общий (`vite.shared.ts`), различаются только имя и порт     |
| CSS Modules               | без CSS-in-JS и без утилитарных фреймворков                        |
| React Query               | сервер-состояние                                                   |
| Zustand                   | клиентское состояние, которого мало                                |
| React Router              | data-router, все маршруты через `lazy`                             |
| React Hook Form + Zod     | формы и валидация                                                  |
| MSW                       | мок-BFF, он же источник данных для тестов                          |
| Vitest + Testing Library  | юниты и компоненты                                                 |
| Playwright                | E2E поверх тех же моков                                            |

Интерактивные примитивы (модалки, селекты, слайдеры) пишутся руками —
готовых headless-библиотек не берём. Поведенческая часть, которая от макетов
не зависит, уже лежит в `design-system/a11y`.

### FSD

В обоих приложениях: `app` → `pages` → `widgets` → `features` → `entities` →
`shared`. Слой видит только слои ниже себя, только в своём приложении и
только через публичный `index` слайса.

Это не соглашение, а правило линтера (`boundaries/dependencies`). Проверено
контрольными нарушениями: импорт вверх по слоям, импорт в обход `index`,
импорт соседнего слайса того же слоя и импорт кода чужого приложения — все
четыре падают.

Исключение одно: сегменты `shared` могут ссылаться друг на друга — но тоже
через `index`.

Слой `app` считается одним элементом: провайдеры, роутер и точка входа
обязаны видеть друг друга.

### Алиасы

`@app`, `@pages`, `@widgets`, `@features`, `@entities`, `@shared` — внутри
приложения. `@ds` — дизайн-система, `@mocks` — моки.

## Деньги

Арифметика с деньгами на фронте запрещена: суммы приходят с сервера
посчитанными, целыми в минорных единицах, строкой.

`design-system/lib/money.ts` даёт брендированный тип `Money` — сложить две
суммы не даст компилятор. Форматирование идёт через `BigInt`, потому что
`int64` не помещается в `number`. Единственная оставшаяся дыра — приведение
строки к float — закрыта запретом `parseFloat` в ESLint.

## Состояния экрана

У каждого экрана их четыре: загрузка, данные, пусто, ошибка.
`design-system/ui/QueryState` требует все четыре обязательными пропсами —
забыть «пусто» или «ошибку» не даст typecheck.

## Дизайн-система

Перенесена из `01 Дизайн-система.dc.html` — макеты лежат в
`Макеты для МФО приложения 2/` в корне репозитория. Бренд «Рублик»:
фиолетовый только под действие, фон всегда светлый, Onest на заголовки и
суммы, Golos Text на интерфейс.

Токены, компоненты, маскот и объекты — в `design-system/`, подробности в
[design-system/README.md](design-system/README.md).

Шрифты локальные, лежат в `public/fonts/` каждого приложения.
